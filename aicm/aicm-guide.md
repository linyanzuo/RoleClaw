# aicm 使用指南

> AI Context Manager：从各规范文件中自动提取高频内容，注入到 AI 上下文。
> 全局命令，无需安装到项目目录，任意项目中均可使用。

---

## 快速开始

在项目根目录执行：

```bash
aicm .
```

---

## 使用方式

### 注入高频规范（默认）

```bash
aicm .
aicm . --inject-high   # 等价的显式写法
```

同名且 inject:high 内容完全一致的文件（如 git worktree 里的拷贝）只输出路径最浅的一份，末尾会有一行 `（已合并 N 份…）` 汇总，规则见下文「副本合并规则」。

### 扫描规范文件树

```bash
aicm . --scan
```

列出磁盘上全部规范文件；注入时会被合并的副本在描述后标注 `【副本：注入内容同 <保留路径>，注入时已合并】`，标题行给出副本总数。

### 生成可折叠/可搜索的 HTML 报告

```bash
aicm . --html                            # 生成 aicm-report.html 并自动用默认浏览器打开
aicm . --html=/tmp/report.html --no-open  # 指定输出路径，不自动打开
```

浏览器里打开的是一个静态单文件页面：目录可折叠展开（默认全部展开，也可一键「展开全部/折叠全部」），顶部搜索框按文件名/路径/描述实时过滤，命中项高亮、自动展开其所在的父级目录。适合规范文件较多、用命令行树状输出不便浏览的场景。与 `--scan` 一样列出全部文件，副本带同样的标注（可直接搜索「副本」过滤）。

**点击文件名**会打开这个文件渲染后的 Markdown 预览（标题层级、表格、代码块、引用块等都有排版），而不是浏览器默认展示的纯文本。原理：内置了一份离线的 [marked.js](https://github.com/markedjs/marked)（`aicm/assets/marked.min.js`，随包分发，不联网），生成报告时把每个规范文件的正文（已剥离 frontmatter）渲染成一个独立 HTML 页，存到 `<报告名>_files/` 目录下（如 `aicm-report_files/context/coding-standards.md.html`），预览页顶部有「查看原始 Markdown 源文件」链接可以跳回原始 `.md`。`<报告名>_files/` 目录随报告一起生成，属于本地产物，不需要提交到 git（各项目 `.gitignore` 已加对应规则）。

### 检测与 CLAUDE.md 的重复内容

```bash
aicm . --check                  # 默认阈值 80%
aicm . --check --threshold=0.9  # 自定义阈值
```

被合并的副本不重复参与比对，同一处重复只报告一次。

### 初始化所有 CLAUDE.md（注入强制执行块）

```bash
aicm . --init
```

### 扫描指定子项目

```bash
aicm ./project-a
aicm ./project-b
```

### 输出到文件（用于对比验证）

```bash
aicm . > /tmp/rules-check.txt
cat /tmp/rules-check.txt
```

## 输出示例

```
==================================================
注入高频规范（以下内容与 CLAUDE.md 具有同等约束力）
==================================================

### 来自 context/git-workflow.md（Git 分支策略...）

| 分支 | 用途 | 操作限制 |
...

==================================================
```

- 每个来源文件单独分组，显示相对路径便于溯源
- 若无任何规范文件，输出提示「未发现带 frontmatter 标识的规范文件，无内容注入」

## 向规范文件添加高频标记

在任意 `.md` 规范文件中，用以下格式标记高频内容：

```markdown
<!-- inject:high -->
- 规范条目 A
- 规范条目 B
<!-- inject:end -->
```

添加后运行一次工具验证输出正确，再提交。
详细写作规范见 `spec-standard.md`（同目录）。

## 工作原理

```
执行命令
  → 递归扫描指定目录下所有 .md 文件
  → 跳过 CLAUDE.md / AGENTS.md（白名单）
  → 检测文件头 frontmatter（--- 包裹，含 frontmatter: 字段）
  → 提取每个文件中的 inject:high 块
  → 合并副本：文件名相同且 inject:high 内容逐字相同的文件只保留一份
  → 按文件路径排序后拼接输出（有合并时末尾附一行汇总）
```

### 副本合并规则

扫描根目录下若存在 git worktree、vendored 副本等（如 `.worktrees/<名称>/…`），同一份规范会以多个路径出现。aicm 会自动合并，避免逐字重复的内容撑爆上下文：

- **判定为副本**：文件名（basename）相同 **且** 提取出的 inject:high 内容完全一致（对内容做 SHA-256 比较）。块之外的正文、frontmatter 描述不参与比较。
- **不会合并**：同名但注入内容不同（例如某个 worktree 分支上改过规范）→ 全部保留；不同名但内容相同 → 全部保留；没有 inject:high 块的文件不参与。
- **保留哪一份**：路径层级最浅（最靠近扫描根目录）的那份，层级相同时取路径字典序最小者，因此输出稳定且指向主工作区文件。
- **各命令的表现**：
  - 默认注入 / `--inject-high`：副本不输出，末尾一行汇总 `（已合并 N 份…）`。
  - `--check`：副本不重复参与比对（同一处重复只报一次），末尾同样有汇总。
  - `--scan` / `--html`：仍列出全部文件（它们是磁盘上的文件清单），副本在描述后标注 `【副本：注入内容同 <保留路径>，注入时已合并】`，标题给出副本总数。
- aicm 不读取 `.gitignore`，也不会跳过 worktree 目录：其中内容有差异的规范仍会被注入。若不希望某个目录参与，请把扫描目录指向更具体的子目录。

## 常见问题

**Q：新增了标记但输出中没有出现？**
检查两点：①文件头有正确的 frontmatter；②`<!-- inject:high -->` 和 `<!-- inject:end -->` 各自独占一行，行首无空格。

**Q：支持子目录吗？**
支持，工具使用 `rglob("*.md")` 递归扫描，子目录内的文件会被自动发现。

**Q：同一份规范在 git worktree 里有多个副本，会被重复注入吗？**
不会。同名且 inject:high 内容完全一致的文件只注入路径最浅的一份，详见上文「副本合并规则」。`aicm . --scan` 可以看到哪些文件被判定为副本。

**Q：怎么跑测试？**
在 `aicm/` 目录下执行 `python -m unittest discover -s tests`（标准库 unittest，无额外依赖）。

**Q：aicm 源码在哪里？**
`RoleClaw/aicm/`（以 editable 模式安装，直接修改源码即时生效，具体本机路径见 `pip show aicm` 的 `Location`）。
