# AI 资产演进规划

> 最后更新：2026-11-19
> 状态：阶段 0 的标准草案已写出，待评审；阶段 1 的 aimm MVP 已实现并接入 Claude 与 Codex 的全局入口文件；Claude 与 Codex 之间的双向读写已实测通过，Claude 在两个项目的新会话里都能主动列出共享记忆中的待办；aicm 与 aipm 的适配未开始
> 关系：本文定义 aimm / aicm / aipm 三个工具的分工与演进顺序；企业侧的阶段目标仍见 [阶段分析.md](阶段分析.md)。

---

## 一、目标与主线

把个人在日常使用 AI 时产生的经验，逐级沉淀为团队可复用的资产：

```
个人记忆（aimm）→ 筛选/提炼 → 提升为 AI 资产 → aipm publish → 角色生效 → 团队生效
```

演进顺序固定为：**个人资产 → 角色资产 → 团队资产**。每一层做完都能独立使用，不依赖后一层。

---

## 二、概念

### 1. AI 资产

AI 资产指三类内容：**文档、技能、规范**。三者的根本区别是 AI 工具加载它们的方式：

| 类型 | 加载方式 | 单位 | 体量 | 典型内容 |
|---|---|---|---|---|
| 规范 `rule` | 常驻注入，每次会话都生效 | 单个规范 | 小，必须精简 | 提交规范、安全红线、协作约定 |
| 技能 `skill` | 按描述触发，命中任务时才读取 | 一个技能目录 | 中 | 代码审查流程、发布流程 |
| 文档 `doc` | 按需阅读，先查索引再读正文 | 一个**文档集** | 大，文件多、层次多 | 业务知识、产品逻辑、系统说明 |

### 2. 成熟度

```
原始记忆 ──提炼──▶ 精炼资产 ──发布──▶ 已发布资产 ──装配──▶ 角色资产 ──汇总──▶ 团队资产
 raw               curated            published
```

- 原始记忆不是资产，是资产的原料。
- 只能由低向高提升，高层的变更不自动回写低层。
- 每次提升都要人确认：AI 起草，人审核。

## 三、三个工具的分工

| 工具 | 定位 | 负责 | 不负责 |
|---|---|---|---|
| **aimm** | 个人资产的产生与保存 | 捕获记忆、提炼为资产草稿、保存到个人仓库、让各 AI 工具读到个人记忆 | 分发、版本、团队 |
| **aicm** | 资产的治理与梳理（辅助工具） | 扫描汇总、去重、分布盘点、结构化、按标准校验、生成索引和报告 | 产生内容、分发 |
| **aipm** | 资产的适配、管理与装配 | 发布、版本、按工具适配安装、按角色装配、汇总为团队资产 | 提炼内容 |

约定：

1. 三个工具通过**文件和《AI 资产标准》**对接，不互相调用代码，各自可以独立演进。
2. aicm 作用于任何一层的资产集合（个人仓库、角色、团队），不只服务个人层。
3. 现状：aipm 已有 skills/rules 的发布、Registry、多工具安装；aicm 已有规范扫描、高频注入、去重与报告；aimm 尚未开始。

## 四、AI 资产标准（阶段 0 的产出）

标准是三个工具的唯一契约，全文见 [AI资产标准.md](AI资产标准.md)；字段定义以该文档为准，本节只列要点。规范正文的写法仍由 `aicm/spec-standard.md` 定义。

### 1. 公共元数据

| 字段 | 取值 | 说明 |
|---|---|---|
| `name` / `description` | 文本 | 用于发现和路由 |
| `asset` | `memory` / `rule` / `skill` / `doc` | 对象类别 |
| `status` | `raw` / `curated` / `deprecated` | 成熟度；是否已发布以 Registry 为准，不写在文件里 |
| `scope` | `personal` / `role:<名>` / `team` | 所属层级 |
| `visibility` | `local-only` / `shareable` | 默认 `local-only`；只有 `shareable` 才能发布 |
| `source` | 工具名 | 来源，用于审计 |
| `update` / `expires` | 日期 | 新鲜度与过期提醒 |

版本号只存在于 aipm 的包清单和 Registry 中。

### 2. 文档类型的专门设计

文档与规范、技能不同：数据量大、层次多、与业务结合紧，必须靠索引按需读取。因此文档是独立类型，单位是**文档集**而不是单个文件。

一个文档集包含：

- **清单**：文档集的名称、版本、适用范围、入口。
- **索引**：人读版和机器读版各一份，由工具生成，不手工编辑。索引逐条给出路径、标题、摘要、层级。
- **正文**：多层目录的 Markdown 文件。

读取约定：

1. AI 工具的入口文件里只放一行指针，指向文档集的索引，不注入正文。
2. AI 先读索引，再按需读对应正文。
3. 文档集变大后，检索入口可以换成 MCP 搜索或向量索引，但索引文件仍是事实源，向量库是可重建的派生物。

工具分工：

- **aicm** 生成和校验索引，检查失效链接、重复内容和层级问题。
- **aipm** 新增 `doc` 包类型，以文档集为单位发布和安装，安装时写入指针而不是内容。
- **aimm** 负责个人层文档的捕获和初步归类。

### 3. 安全底线

- 任何层级都禁止写入密码、私钥、令牌等秘密正文。
- 写入和发布前都要做秘密扫描，不通过即拒绝。
- 从 `local-only` 改为 `shareable` 必须是显式的人工动作。

## 五、个人资产仓库

阶段 1 使用**单个私有仓库**，内部两级存放：

```
<个人资产仓库>/
├── memory/          原始记忆（raw），平铺存放，带一份索引
└── assets/          精炼资产（curated 及以上）
    ├── rules/
    ├── skills/
    └── docs/        每个子目录是一个文档集
```

决定与理由：

- 先用单仓库验证 aimm，降低前期复杂度；公开与私有数据如何隔离，等要开放时再定。
- 为了让以后拆分的成本低，现在就遵守两条约束：`assets/` 下的内容不引用 `memory/` 的路径；`memory/` 的内容全部标 `local-only`。
- 已知限制：Git 平台的权限一般以仓库为单位，单仓库无法对两级目录分别授权。这一点在"开放仓库"那一步再处理，届时可按目录拆成两个仓库。

## 六、演进路线

### 阶段 0：契约

- 产出：《AI 资产标准 v1》，含元数据、生命周期、目录布局、文档集结构、隐私等级。
- 验收：三个工具各自"读什么、写什么"能对照标准说清楚。

### 阶段 1：个人资产，跑通最小闭环

- **aimm MVP**：初始化仓库、添加记忆、列出、提炼为资产草稿、校验、同步到 Claude 和 Codex。
- **aicm**：能扫描个人仓库，输出去重与分布报告，按标准校验，为文档集生成索引。
- **aipm**：能把个人仓库里 `curated` 的规范和技能发布到个人 Registry 并安装。
- 验收：一条真实记忆走完 `raw → curated → published`，并在 Claude 和 Codex 的新会话里生效。

### 阶段 2：个人资产完善

- 适配 Cursor、Qoder、GrokBot。三者的记忆与规则读取机制需要先逐个查证，再定适配方式。
- aipm 新增 `doc` 包类型；文档集的发布与安装跑通。
- aimm 提供 MCP 服务，各工具可实时读写；部署到私有服务器，可与 Registry 同机。
- 数据量上来后再加向量索引。

### 阶段 3：角色资产

- 以 aipm 现有的 `profile` 作为角色的载体，把个人资产贡献到角色。
- 建立角色级的归属与评审：谁能提交、谁审、谁合并。
- aicm 在角色层做跨人去重，把相似经验合并为一份标准资产。

### 阶段 4：团队资产

- 把多个角色资产装配为团队资产，对应组织架构。
- 补齐团队级的权限、版本策略、废弃与迁移流程。
- 与 [阶段分析.md](阶段分析.md) 中的企业侧目标对接。

### 后续

- 活动沉淀：把各工具的会话和操作摘要纳入记忆来源。

## 七、设计原则

1. **标准先于工具，文件先于服务**：MCP 和向量库都只是同一份文件的另一个出口。
2. **单向提升**：低层向高层提升，不反向覆盖。
3. **每层可独立使用**：阶段 1 完成即对个人有价值。
4. **隐私默认保守**：默认不共享，发布必须显式。
5. **事实只写一处**：正文只存在于一个位置，其他位置是安装副本或引用。
6. **按加载方式划分资产**：常驻的进规范，触发的进技能，按需的进文档；规范保持精简，大体量内容一律进文档。

## 八、已定事项

| 事项 | 决定 |
|---|---|
| 演进顺序 | 个人 → 角色 → 团队 |
| 首个工具 | aimm |
| 个人仓库 | 单个私有仓库，两级存放；开放时再考虑隔离 |
| 文档 | 独立资产类型，以文档集为单位，带索引，按需阅读 |
| 起步形态 | 文件同步，之后 MCP，数据量大后再加向量库 |
| 首批工具 | Claude、Codex；设计时兼顾 Cursor、Qoder、GrokBot |
| 部署目标 | 最终部署到私有服务器 |
| aimm 代码位置 | 本仓库 `aimm/`，与 aipm、aicm 并列 |
| aimm 实现语言 | Python，与 aicm 一致 |
| 个人资产仓库的同步 | 先用本地 Git 仓库，远程仓库后补 |
| 提炼时的模型调用 | aimm 不调用模型、不配置密钥；它只输出候选，由当前使用的 AI 工具起草，人确认 |
